## A：折叠与锁定

### TC-001：锁定条只显示有用入口

对应需求（Trace）：R01、R05；优先级：P1。

**测试场景**：独立便签折叠、锁定及找回。

**测试数据**：公共便签，初始未锁展开。

**测试步骤**：

```text
1. 点−折叠，再钉住
   预期：条高27pt，标题与解锁可达；＋、×及层级操作隐藏，不可拖动或展开。
2. 从管理器尝试编辑、收纳、删除同一ID
   预期：整张锁定仍有效，无内容／可见变化。
3. 解锁，点×，从管理器找回再点＋
   预期：操作恢复，×仅收纳；找回同ID且仍折叠，展开使用当前全局高度，内容不变。
4. 对照内容修改时间
   预期：以上整理动作均不改时间。
```

## B：统一打开高度

### TC-002：设置、草稿、边界及小布局

对应需求（Trace）：R02、R05；优先级：P0。

**测试场景**：管理页面保存全局高度，验证下次打开和175／177.5pt可读写。

**测试数据**：新空库，公共长文／12待办；有效值175、177.5、500、1000；无效值空、abc、NaN、Infinity、-Infinity、174.9、1000.1。另用全新合成库在正式布局保存边界注入失败。

**测试步骤**：

```text
1. 打开管理页面，未改设置从文件新建A
   预期：设置页高度显示默认190pt，新窗宽270pt、高190pt，字体未缩小。
2. 输入500但不保存，新建B；保存后看A/B，再新建C
   预期：未保存草稿不生效；保存成功后A/B不跳动，C为500pt。
3. 手动缩放A为600pt，整理B（如钉住再解锁），再从管理器显示已经打开的A；随后真正收纳再找回A；折叠C，保存175，再展开C
   预期：整理B及再次显示已开A都不让A的600pt／上沿跳动；只有真正收纳找回A才用500pt；C仍27pt直到展开，展开为175pt；保存设置不改变其他已打开窗口。
4. 分别保存175和177.5，再打开对应长文便签；不先放大，滚动编辑第100行、勾选第12条、添加再移除新增待办
   预期：正文末尾、待办和操作均可达，字体不变；两种高度均成立。
5. 两种短高度分别注入正文保存失败，编辑已确认文字后滚动查看错误并触达重试；解除故障重试
   预期：可见错误、已确认文字保留，重试入口可用，恢复后落盘；不因错误区域而永久裁掉内容或操作。
6. 逐个输入无效值并保存，每次回到管理页面查看草稿与生效值再新建
   预期：每个值均被拒绝且显示原因，原生效值不变、草稿仍可修正，新窗不采用无效值。
7. 记录保存布局字节，输入500并注入布局保存失败后保存；解除故障前比对文件，并新建或收纳找回一张量高；然后解除故障重新保存，另进程读回
   预期：失败可见、草稿500和旧生效值保留，重试前文件字节不变、新打开仍旧高度；只在重新保存成功后生效并跨进程读回500；已打开窗口仍不跳。
8. 保存1000并新建，随后保存177.5；正常退出重开
   预期：1000合法；屏幕不足时显示高度暂限可见区、顶部和内容操作可达，已保存值仍1000而非被偷偷改写；重启后读取最后177.5。
9. 分别从管理器＋、空态和边缘有效拖出新建
   预期：均用同一已保存高度；边缘真人操作另记录，程序调用不冒充手势验收。
```

### TC-003：旧记录打开、严格兼容与跨进程

对应需求（Trace）：R02、R03、R05；优先级：P0。

**测试场景**：旧NoteLayout v1无新字段记录在下次打开统一高度，不批量减半。

**测试数据**：合成旧库A展开355pt、B锁定展开600pt、C折叠存展开400pt、D收纳350pt、E回收站500pt、F无placement；宽270，公共内容；v1缺新全局高度／层级字段。独立坏格式分支：未知version、截断JSON、新高度字段null／字符串／174.9／1000.1、新层级null／数字／未知枚举，旧frame无效；记录布局原始字节与设置快照。

**测试步骤**：

```text
1. 启动新版读取旧库，尚未移动／整理前比对布局原始字节，检查A/B/C
   预期：读取不重写文件、不批量缩放、不创建升级备份；A/B按默认190打开，B仍锁；C仍27pt。宽、x、上沿、纸色、内容和内容时间保持（越屏可访问限制另记）。
2. 展开C，收纳找回D，恢复并显示E，显示F
   预期：各展开窗口均190，而非按旧高度各自减半；ID不变，缺层级默认浮顶。
3. 保存高度500，现有窗口不跳动；正常退出，另进程重开，再退出重开
   预期：每次启动恢复展开窗口500，C若先折回仍27pt；B仍锁、宽/x/上沿保持；没有再次减半或全局值被手动尺寸覆盖。
4. 将A沉底、B保持浮顶（B已锁不切换），正常退出另进程读取并恢复
   预期：全局高度500、A沉底／B浮顶按张保留，SQLite模型与内容时间不变。
5. 分别打开每个坏格式分支并比较原字节
   预期：报错并保留原文件，不把null／错类型／坏值当缺字段、不清空重建；未知版本仍拒绝。
6. 静态核对旧应用的350pt下限与新布局低于350的记录
   预期：明确记为不承诺旧版无损回读，不用更改version／覆盖库来假装降级成功；本用例不执行真实库降级。
```

## C：沉底与浮顶

### TC-004：真实遮挡与桌面找回

对应需求（Trace）：R03、R05；优先级：P0。

**测试场景**：同一桌面中逐张切换便签与普通应用窗口的前后关系。

**测试数据**：公共A/B未锁，普通应用对照窗口不含敏感资料。

**测试步骤**：

```text
1. 新建A/B，激活普通应用并重叠
   预期：都在普通窗口之上，只提供“沉底”。
2. 对A点沉底，再使用普通应用
   预期：A在下、B在上，A仍可见记录而非收纳／删除。
3. 在当前桌面逐个最小化对照和其他遮挡窗口，不退出／收纳PaperDock、不切Space；直接点击A正文编辑，再恢复同一对照窗口
   预期：桌面可找到并编辑A，只提供“浮顶”；恢复普通窗口后A仍在下，不因点击自行浮顶。
4. 再最小化对照，点A浮顶，恢复对照
   预期：A到普通窗口之上，操作变“沉底”，两种互斥。
5. 折叠A切换层级，再钉住；解锁展开，再钉住
   预期：未锁折叠可切换；展开／折叠锁定都无有效层级入口；解锁恢复正确操作。
6. 对同一锁定ID调用正式AppModel与Store层级请求；对照未编辑分支内容时间
   预期：不能绕过锁定，权威状态和真实窗口层级不变；仅层级动作不改内容时间。
```
