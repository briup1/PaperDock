钉住之后，不再被误挪或误改

报价便签已经摆好，点击顶部“钉住”，不只禁止拖动，也禁止缩放、标题正文、待办、配色、收纳及删除；仅留解锁入口。管理器同一张也只读。正常退出仍可用，重开保留锁定与原位置。

当前正式版以稳定ID共享Store，浮窗通过AppKit显示，未保存位置和锁定，也未限制跨入口修改。此为本轮直接源码核对，不是新功能已实现。

旧：便签始终能移动与编辑 → 关闭收纳
新：顶部钉住〔新增〕
      ↓
    固定整张，其他入口同样不可改〔修改〕
      ├─ 解锁 → 恢复原操作
      └─ 正常退出重开 → 同ID、原位置、仍锁定〔新增〕

在现有代码上怎么承接

NoteEditor顶部钉住/解锁
  ↓
结束有效字段编辑，检查同ID当前状态
  ↓
Store保存锁状态＋钉住时浮窗frame
  ├─ 保存失败 → 可见错误，不声称钉住成功
  └─ 成功 → 发布状态
              ├─ 编辑器/管理器禁用修改、关闭旧草稿
              └─ NoteWindows禁拖移缩放/拦关闭

所有内容/配色/收纳/删除提交入口
  ↓
Store/AppModel再查当前锁状态 → 已锁即拒绝
  ↓
旧草稿/旧删除确认不能迟到绕过

锁的权威在Store，不仅灰掉按钮。浮窗frame由NoteWindows在钉住时提供；恢复窗口先应用保存frame再显示。锁定面板不能经标题栏、边缘缩放或关闭改变；从管理器解锁也同步更新面板。未确认的输入法候选不虚构为保存正文，锁后delegate仍须拒绝写入；解锁不重造新便签。

锁定属于整理动作，不改内容修改日期。设置新建配色是全局独立入口，可沿用；但从已锁A打开前的配色草稿不允许借切换范围提交任何变化。当前单屏是恢复范围，多屏/断屏不是本轮新增承诺。

右键哪张，就只整理哪张

当前选中A，右键B卡片删除，应确认B而不是A。现有编辑器已有软删除请求与确认，本次复用该语义，不增加永久删除。

全部列表卡片右键〔新增〕
  ↓
菜单绑定被点卡片的稳定ID，不读取当前选择
  ├─ 已锁 → 删除置灰
  └─ 未锁 → 删除确认〔复用〕
               ├─ 取消 → 不变
               └─ 确认 → 重新检查该ID是否锁定
                            ├─ 已锁 → 拒绝、不收纳
                            └─ 未锁 → 仅该张入回收站/收起浮窗

在Manager卡片添加contextMenu，在管理器层承接确认提示，确认对象由AppModel保存的pending ID决定；不能把删除按钮绑到selected。已有编辑器删除也走同一最终校验。列表空白无删除菜单；其他筛选不额外拓展入口，全部列表中的搜索结果同样精准绑定ID。回收站恢复仍恢复为收纳。

沿用现有存储，不破坏试用资料

沿用Swift/SwiftUI、AppKit、NSTextView与Core Data以及现有离线CLT构建，不引入包或改变全局配置。当前Core Data模型无锁定/位置且禁自动迁移；推荐把这两项非内容状态存为同一数据目录内的小型原子JSON，按稳定便签ID关联，避免本轮改SQLite模型或自动升级现有试用库。

没有该文件表示旧记录默认未锁，旧Core Data原样读入。文件存在却损坏时可见报错且保留原文件，不把“损坏”当“没有”重置锁；版本/有限坐标/尺寸需验证。先落盘成功再发布锁定/解锁，失败保留旧锁状态；内容保存与退出仍走已有成功/失败链。应用级独占目录锁同时保护此文件，不增加另一个写者。只记录本轮需要的钉住frame和状态，不扩展全窗口布局系统。

专项本次决定
数据/兼容：涉及旧SQLite模型不改；新文件可缺省不可损坏静默重置；独立副本验证旧库读回。
状态与入口：涉及Store最终锁校验、UI状态同步、迟到草稿/删除重新验证，单进程主线程沿用。
权限/外部：无新增不安装、不申请权限、不发布、不操作日常资料。
性能/多屏：不扩展仅钉住/解锁保存少量状态，不加轮询/服务/布局框架。

可观察验收引用用例v0.1 TC-015～019；回归只覆盖编辑/配色取消、收纳/软删除和正常退出直接路径。一个持续实现工作包覆盖锁定、位置和菜单，因为它们共享Store/AppModel保护；实现冻结后由未写代码者独立检查、独立构建与定向验收。CLI/自有控件探针不冒充真人拖动、真实菜单或输入法候选。
