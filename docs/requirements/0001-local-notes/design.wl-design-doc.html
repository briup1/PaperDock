SEC 01 / 06

先让一张便签在 Mac 上可靠地工作

用户正在浏览网页，想到“明天联系客户确认报价”，从屏幕边缘拖出便签写下；收纳后能通过日期、标题和全文搜索找回。关闭软件再打开，记录和配色选择仍在。这是本地个人效率工具，不是知识库、云同步服务或跨平台工程。

推荐：Swift＋SwiftUI＋AppKit＋NSTextView＋Core Data。
普通管理界面用 SwiftUI；独立窗口、焦点与边缘入口用 AppKit；正文用系统文本编辑器；记录与设置保存在本机。无服务器、账号或第三方运行时。

已经证明的部分

当前机器 macOS 26.5.1／arm64／Swift 6.3.3，仅 Command Line Tools，已实际编译 AppKit/Core Data。实现者及未写代码的独立审查者分别在新目录以三个独立进程跑通窗口可见、中文字符串编辑、待办与 Core Data 保存、正常退出后固定／随机配色读回；反向失败码与坏库不覆盖另有独立检查。这些是程序自驱，不是真人输入或完整产品验收；SwiftUI承载及桥接尚未实测。

关键人工验证现已补齐到本机单屏范围：用户已分步确认中文输入法、浏览器跨应用置顶/焦点、收纳找回与正常重启保留；新版入口的靠近探出、移开收回、拖出收回与再次唤出也反馈正常。协调者核对回调日志及两轮实例均正常退出。隐藏时仍保留右侧中段2pt命中条，不是零占用；这些结果不外推多屏、全屏、旧系统或完整产品。用户本轮已批准按此单屏普通窗口边界正式实施。

当前网页原型只在浏览器内工作、刷新丢数据；原生实验是可丢弃的一张便签，不直接升格成正式代码。用户本轮明确选择A的均衡三栏作为正式管理界面；B/C不进入首版。

本轮证据与来源
  • 原生实验 README：环境、复跑命令、程序证据与历史未验边界；后续真人结果见方案第6节链接的两份manual-result.md，以后者为最新状态。
  • 独立用例与原生准备性审查：G1–G4步骤已复核闭合，独立复跑命令、退出码与PID清理均有记录；不代表全部正式用例已执行。
  • 网页原型实际走查：不能代替原生证据。

SEC 02 / 06

想到一句话，不先打开管理器

当前：网页仅为产品原型。原生实验已用真实NSScreen坐标和非激活面板完成右侧中段2pt命中区→24pt探出；独立程序检查已通过，用户也实际确认靠近/离开/拖出/再次唤出正常。此处是本机单屏验证，不是全部屏幕边界与系统版本认证。

同一例子：拖出后写“明天联系客户确认报价”，自动标题为“明天联系客”；补一条“核对价格”待办。便签可见时在普通窗口上方，点击其他应用后键盘应归其他应用，不因置顶就抢输入。

原型：页面内拖出 → 网页编辑 → 内存保留

目标〔新增原生承接，产品规则保持〕
指针靠近屏幕边缘
  ↓
显示便签入口 → 向桌面拖出一张
  ↓
输入正文与待办，不必先起标题
  ↓
便签保持可见；焦点随实际点击转移
  ├─ 继续使用其他应用 → 便签不抢键盘
  └─ 点击便签 → 继续修改同一记录
  ↓
关闭便签 → 收纳，不删除
  ↓
菜单或管理器显式找回同一张

怎么接到系统能力

NSScreen 的屏幕与可用坐标
  ↓
AppKit 边缘入口 + 鼠标追踪/拖动
  ↓
创建唯一便签ID → AppKit 独立面板
  ↓
SwiftUI 控件 + 桥接 NSTextView 正文
  ↓
统一更新记录 → 本地保存 → 列表同步

每张便签由同一窗口管理器按ID复用，不因菜单、拖动、列表点击产生多个副本；关闭映射为收纳。使用正常公开窗口层级控制普通窗口前显示，不使用极高系统层级盖住所有系统界面。

正文保留系统中文输入、选区、复制粘贴与撤销能力；待办用独立条目控件，含文字、完成状态、顺序。不从零造光标或把正文和待办塞成完整 Markdown 编辑器。系统输入法组合输入时不重建编辑器、不提前提交未确认文字。

已经核实与还需核实

实验的 NSWindow.isVisible、key window 与 first responder 分别观察；早期“可见就立即断言焦点”的时序错误已保留并修复。窗口level比较及同一应用普通演示窗口叠层只证明配置和应用内结果，不代表浏览器等其他应用前的实际行为。

推荐沿本轮已验证的自有窄非激活面板与NSTrackingArea追踪入口，不申请全局键盘监听或辅助功能权限。默认隐藏仍在主屏右侧中段保留2pt、130pt高的命中区，靠近展开24pt；拖动过程中不提前收回，松开完成或取消后收回。此占用是明确取舍；Dock位于右侧等冲突、多屏、全屏、Space须在后续支持范围中验证，不作“永远置顶”承诺。

对应 TC-001、TC-006、TC-010。本机人工关键路径已有用户确认；完整正式入口和多条记录仍须按用例重跑，不能把实验通过直接记成成品验收。

SEC 03 / 06

收纳之后，仍能按最近改过的内容找回

当前：全部列表、正文摘要、标题、修改日期分组和搜索在网页原型已实际走查；本轮一张便签原生实验没有完整管理器，不能据此说原生搜索已实现。

同一例子：昨天记录的报价便签今天补“确认40HQ价格”，应进入今天分组；收纳后搜索“40hq”仍能找到；手动命名“客户报价跟进”后，改正文不会覆盖标题。

收纳或保留桌面便签〔保持同一记录〕
  ↓
打开全部便签 → 按最后内容修改日期分组
  ↓
看标题 + 正文摘要 + 可见/收纳状态
  ↓
搜索标题 / 正文 / 待办文字
  ↓
选中同一ID → 继续编辑或显示到桌面
  ↓
内容变化 → 更新日期与列表，不抢走编辑对象

改哪里、如何保持一致

新增 SwiftUI 三栏管理器，使用同一份本地记录，不为窗口和列表分别保存两套正文。持久化记录保留ID、手动标题、正文、内容修改时间、可见/收纳、删除状态和单张纸色；待办按稳定ID关联便签并保持顺序。自动标题与摘要从内容推导，不额外维护容易过期的副本。

Core Data 读取记录和待办
  ↓
按筛选 + 关键词取匹配集合
  ↓
按内容修改时间倒序 → 以本地自然日分组
  ↓
列表显示派生标题与摘要
  ↓
编辑器始终绑定稳定便签ID
  ↓
内容改变后重算匹配，不暗换编辑对象

只在没有手动标题时，从正文及待办可见内容取前5个字素；忽略原型已接受的空白/行首列表标记，Swift以Character处理组合字符。单条标题规则应有纯待办、换行、家庭表情等测试，不把实验“只取正文”当正式规则。

正文、标题、待办增删改或完成状态更新内容修改时间；移动、缩放、纸色、收纳、删除恢复不更新。跨日期边界重新计算组标题。相同修改时间以稳定ID作次序兜底，不赋予其额外业务含义。

搜索沿用已接受规则：标题、完整正文与待办，英文大小写不敏感，当前筛选限定范围；回收站单独检索。初期个人本地查询先用Core Data筛选与必要派生匹配，不引入搜索服务器或未证明需要的索引系统。搜索中编辑导致不再匹配时，保留当前编辑器并提示；不得悄悄把后续输入写给另一个结果。

对应 TC-002～006、TC-010～012；实验不实现的管理链路须留到正式应用逐项验收，不能由原型覆盖。

SEC 04 / 06

颜色跟着便签，设置跟着下一张

当前：网页刷新会重置。原生实验用Core Data SQLite存一张便签快照，三个进程正常退出、重开已读回纸色、模式和随机池；实验色值与单待办模型是简化，不是最终产品数据模型。

同一例子：报价便签保持淡绿；用户在选色盘调出蓝色，选择“以后固定”，下一张才用蓝色。若选择“加入随机”，蓝色进入六种内置纸色的池，重复加入不增份数。退出重开仍保留这两类选择。

新建便签
  ↓
读取当前新建配色设置
  ├─ 固定 → 使用固定色
  └─ 随机 → 从内置六色 + 主动加入色取一个〔允许重复〕
  ↓
写入这张便签的实际纸色 → 后续不跟默认变化

选色盘调整 → 实时预览〔不保存〕
  ├─ 取消/关闭 → 丢弃本轮草稿
  └─ 应用
       ├─ 只改当前 → 修改单张颜色
       ├─ 以后固定 → 保存模式与固定色，旧便签不改
       └─ 加入随机 → 去重入池并切随机，旧便签不改
  ↓
正常退出 → 再开同一数据目录 → 记录与设置读回

本地数据与草稿怎么分开

正文/待办/标题已确认的编辑
  ↓
统一记录状态 → Core Data 同一写入边界
  ↓
成功：显示已保存
失败：显示未保存、保留内存编辑，不假报成功
  ↓
退出前提交当前有效编辑
  ├─ 保存成功 → 正常退出
  └─ 保存失败 → 提示并阻止静默退出

配色预览草稿〔只在弹层内〕
  ↓ 只有应用才提交
单张记录 或 新建设置事务 → Core Data保存

正式模型采用便签、待办、配色设置三个直接业务边界。设置包含随机/固定模式、固定色、主动加入的自定义色及保存的颜色；随机池用已批准内置六色加用户加入色推导去重。每张便签保存已经选中的实际色，不在每次显示时重抽。

内置色沿用原型：纸白#FFFEFA、暖米#F5EEDC、羊皮纸#E9DDC6、浅灰#EDF0ED、淡绿#E5EEDC、深灰#303731。选色盘为主、色号辅助；正文自动匹配深浅文字，控件与选中状态须另外验可读性，不把正文对比度当整页验收。

正式应用数据放用户Application Support的本应用私有目录；开发/实验可注入独立目录，不能与日常数据混用。Core Data加载失败不当空库覆盖；迁移前保留旧库并使用有版本的模型，迁移失败保留原文件和可见错误，不自动清空。无现有正式库需要回填，不做云端迁移或复杂同步。

写入频率与正文输入法配合由正式实现聚焦确定，不承诺未测的毫秒时限。目标是正常退出后完整保留；磁盘满、断电、强杀下零丢失不在已确认保证内，不能用正常重启通过替代故障恢复测试。

对应 TC-007～009、TC-014。重启验收需比对ID、内容、两种待办状态、单张色、收纳、固定色和随机池，而不只是看到文字还在。

SEC 05 / 06

只增加本地便签所需的系统能力

专项判断与最小处理
数据与存储涉及：内容、状态和配色跨正常重启保留；Core Data，加载失败不覆盖。
接口与协作涉及本进程模块协作：稳定ID连接窗口/编辑器/列表/存储，无对外API。
状态与异步涉及：输入法组合输入、保存状态、配色草稿与应用；统一写入边界，UI在主线程，不用两套编辑状态。
安全与权限涉及本机数据隔离与系统交互；不用全局键盘监听、屏幕录制或辅助功能作为默认依赖。权限确有必要先说明再授权。
性能与容量待确认规模；目前无可承诺阈值。首版实测启动/输入/搜索，再据真实瓶颈优化，不先加缓存服务。
外部依赖/发布无服务器、账户、CloudKit或第三方运行时；本轮不签名分发/上架。CLT可编译实验，不证明正式打包与旧系统兼容。

明确的取舍

SwiftUI适合管理与设置，但不强求它独自完成特殊窗口行为；AppKit直接承接这部分。NSTextView保留成熟输入行为，待办独立控件，避免自研编辑器。Core Data已经在本机新进程读回，不为未来同步提前接CloudKit，也不引入Electron/Tauri来重写已确定的Mac定位。

实验中的Snapshot包只证明持久化机制；正式数据需要按便签查询与待办关联组织，不将实验代码原样搬进产品。最低macOS版本推荐15作为设计候选，但尚未在15验证；若最终只支持当前系统，须作为支持范围决定明确告知，不能默认降级。

支持边界不偷换

  • 普通窗口置顶是目标；全屏应用、Space与Stage Manager没有实际证据，不承诺覆盖。
  • 历史常显标签已由新版隐藏探出实验替代并经用户验证；保留2pt命中区域的取舍必须在正式产品中明确，不能宣传为零占用。
  • 不做同步、Windows/iPhone、图片、复杂富文本、标签、账号、支付或全局系统快捷键。
  • 回收站只提供恢复，无自动清理/永久删除；后续不以“清理原型”为由删除用户记录。
