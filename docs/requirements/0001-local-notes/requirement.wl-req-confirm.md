# 需求 0001：随手记下，集中找回

## 本轮确认与阶段推进

**最新授权（覆盖下方历史阶段限制）**：用户在方案v0.2及两轮原生人工验证后，明确要求“采用 A 三栏管理界面，首版先保障当前 Mac 单屏、普通窗口场景 再组织正式开发与独立验收”。方案已批准，进入正式本地实现；无新增业务规则，用例仍v0.3。A已选定；历史B/C比较只属原型记录。只用项目内合成数据开发验收，不安装工具、不改权限、不设开机启动、不初始化/提交/推送Git、不发布、不操作日常资料。完成与否以正式应用独立验收记录为准，实验通过不替代。

用户在原型v0.3交付后明确“原型与交互没问题”，随后接受“简洁实施方案＋最小原生验证，结果进入方案再批准正式开发”的建议。本稿产品目标已批准；历史正文中的待核验/未授权说明按来源保留，最新阶段以本节为准：配色增量已实际走查，见[原型验证报告](../../prototype-validation.md)；正式用例独立审查本轮执行，不能由产品批准代替。

本轮允许制作并运行项目内隔离的一张便签原生实验，核实边缘拖出、普通窗口置顶/焦点、编辑/待办、本地自动保存及正常退出重开保留；不授权完整产品实施、安装工具、修改系统权限、开机启动或发布。A/B/C具体外观仍未明确选定，可在方案推荐，不阻塞系统能力验证。异常退出零丢失或保存时限未承诺。原生未验不能误写成已验。

## 需求重定义

**原始诉求**：先把全套产品原型与用户故事跑通，再讨论颜色风格；以 Brim 的便签交互为参考。

**最终目标**：Mac 使用者工作中随手留下一句话或待办，桌面整理后仍能在集中管理处凭内容找回，不必先起标题或分类。

**异议**：不能把网页模拟的边缘拖出、置顶和内存记录当作可交付 Mac 能力。建议先确认记录、找回与整理的路径，再确认外观；正式能力验证留待后续获准阶段。在现有材料范围内，尚不足以断言参考交互是最佳路径（Q08）。

**重定义后的需求**：围绕“记下→辨认→按最近修改回顾→搜索找回”确认最小本地便签体验；产品确认阶段已结束，当前按开头授权进入方案与隔离原生实验，不启动完整正式实施。

## 用户故事

- US01：As a **Mac 使用者**, I want **从屏幕边缘拖出独立便签并置顶记录**, so that **不打断手头工作也能留下闪念**。R01/R02；[原型桌面](../../../prototype/paperdock.prototype.html#desktop)。
- US02：As a **记录者**, I want **不命名也能靠标题与摘要辨认，必要时手动命名**, so that **快速区分内容且保留自己的命名**。R03；[管理入口](../../../prototype/paperdock.prototype.html#manager)。
- US03：As a **回顾者**, I want **按最近修改分组并搜索标题与全文，含收纳**, so that **记不清放在哪里也能找回**。R04/R05；[搜索入口](../../../prototype/paperdock.prototype.html#search)。
- US04：As a **办事者**, I want **在文字便签里管理待办**, so that **记录能变成可完成的行动**。R06；[编辑入口](../../../prototype/paperdock.prototype.html#editor)。
- US05：As a **阅读便签的人**, I want **选择内置或自定义纸色**, so that **按个人偏好阅读内容**。R07；[配色入口](../../../prototype/paperdock.prototype.html#palette-dialog)。本轮随机/固定/单张与取消规则见 P02，产品方向已接受。
- US06：As a **整理桌面的人**, I want **收纳后仍能在管理处找回**, so that **清理桌面不等于丢记录**。R02/R05；[管理入口](../../../prototype/paperdock.prototype.html#manager)。删除恢复 P04 已获本轮其余行为接受。
- US07：As a **首次或暂未找到内容的人**, I want **知道当前为空及下一步入口**, so that **能开始记录或继续找回**。P05，已获本轮产品反馈接受；[空状态入口](../../../prototype/paperdock.prototype.html#empty-reset)。

## 已确认规则

确认依据均为 E01 的对话摘要，不冒充逐字原对话或本稿整体批准。

- R01：目标为 Mac 本地使用。只读网页原型不是最终软件，本地保存与退出恢复尚未实现（细节 Q07）。
- R02：参考边缘拖出新建、独立便签、普通窗口置顶以及可见/收纳；所有便签可集中管理。这里的置顶指目标中的普通应用窗口前可见，原型无法验证系统层行为；具体范围 Q08。
- R03：未手动命名时，以正文前 5 个可见字符自动命名；不足 5 字全显。可手动命名，正文后续变化不能覆盖手动标题；集中列表提供正文摘要以辨认。可见字符细则与清空手动标题见 Q01。
- R04：集中列表按最后修改时间分组，不按创建日期。现有原型的内容修改动作、本地日期与倒序行为已获产品反馈接受；原生跨日验收边界见 Q02。
- R05：支持标题及正文全文文字检索，范围包含已收纳便签。全文不等于只搜列表截断摘要；大小写、待办文字及筛选组合见 Q03。
- R06：第一版保留文字与待办，用户已对先前第 3 条范围建议回答“同意”，不再重复询问范围。待办操作细节按 Q06 评审。
- R07：提供常见阅读软件风格的内置纸色及自定义颜色；用户本轮确认以可视化选色盘为主入口，点选/拖动调整颜色与明暗并实时预览，不懂或不输入色号也能完成选色，色号输入仅为可选辅助并与选色盘联动（E04）。不作护眼疗效承诺；二维色盘、色相条等精确视觉形式仍为候选，本轮新建随机/固定/单张及取消规则见 P02（E05），精确界面仍为原型实现，不等于正式设计批准。

P02 新建配色规则（产品决定 E05）：
- 初始模式为随机，池为内置六色。所有新建入口共用此规则；每次随机可重复，不强制相邻不同。
- 配色弹层三种范围：只改当前、以后固定使用此颜色、加入随机配色。只改当前不自动加入随机池；固定模式之后的新建统一用固定色。
- 自定义加入随机：颜色去重加入“内置＋主动加入色”池，并切回随机模式；界面明确说明这一操作结果。设置可切回已有随机池，保留已加入自定义色，不必添加当前预览色。
- 未点击应用前不改固定模式、随机池或旧便签；取消/关闭/Escape 丢弃本轮预览及新增颜色。范围变化不重染任何旧便签，也不改变内容修改日期。

Q01/Q03/Q06：沿用当前原型的自动标题、搜索组合、待办操作。搜索中不再匹配时保留同一编辑对象并提示，继续输入不串写、不丢失（TC-005）；这些现有行为已获产品反馈接受。Q08：原生边缘监听、跨应用置顶与系统约束仍待正式环境可行性验证；不可把网页或历史原型冒充原生结果。
