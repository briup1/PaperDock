# 0005：待办更紧凑，便签可折成标题条

## 已确认规则

1. 缩小独立便签已有待办列表与下方“添加待办”之间的纵向空白；字号/勾选框及操作保持，不改管理器布局。
2. 独立便签顶部×收纳左边新增−。点−隐藏日期/正文/待办等内容，窗口缩成保留当前标题的紧凑条（手动优先，否则原自动标题；空白仍用空白便签）。保留原纸色，在桌面可见，不是系统Dock最小化或收纳。条内＋恢复同一便签原展开大小、内容和待办，不另建记录；×仍收纳。
3. 折叠后保持顶部位置/原宽度，未锁时可拖动；展开在当前标题条位置恢复原展开尺寸，不跳回拖动前的位置。折叠属于整理，不更新时间/搜索内容。
4. 已钉住沿用整张锁定：先解锁才可折叠或展开。锁定的折叠条仍要有可达解锁入口；不能因折叠藏掉唯一解锁。内容仍可从管理器正常查看编辑（未锁时），标题条同步同ID标题。
5. 正常退出重开保留折叠状态、条的位置与原展开尺寸；收纳找回仍同一张且保持折叠。已有旧锁/frame数据向后兼容，缺新增字段按未折叠；坏数据不静默重置。原SQLite模型不改，锁与折叠元数据原子落盘后发布，失败可见不伪成功。

## 当前代码事实与局部方案

当前独立面板borderless/resizable/nonactivatingPanel，默认270×355pt；compact有自有工具栏拖区/×收纳与22pt图标命中区，底部无保存成功文案。Store以NoteLayout.json记录NotePlacement lock/frame，高下限350，只记录展开尺寸，不能把折叠条小高度当作原有合法展开frame。管理器/浮窗共享Store/AppModel与稳定ID。

复用同一链路新增整理状态：NotePlacement在兼容解码旧字段基础上增加折叠标记（缺省false），保存的frame含当前展开宽高及恢复所需位置；窗口由NoteWindows统一计算标题条frame与展开frame并遵守锁。只做本需求直接必要的帧同步/保存，不做通用布局管理器。Store最终保护已锁动作，元数据真实原子写成功才切状态，不降掉原有限值和尺寸校验。compact Editor折叠分支仅标题/必要控制，不实例化隐藏正文；恢复不丢已确认编辑，不伪保存未确认IME。拖区不能拦按钮/正文选字，程序退出仍原保存链。
