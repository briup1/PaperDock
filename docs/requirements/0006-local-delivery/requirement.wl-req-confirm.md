# 需求 0006：PaperDock 改动开发与本地交付

## 现状：修改后仍需手动切换应用

当前代码可确认：构建能产生应用，但不提交、不安装；运行脚本只在二进制缺失时构建。运行观察：2026-10-25 有一个来自开发产物的 PaperDock 正在运行，显式使用项目内自定义数据目录。Git 忽略安装包，但本地 dist 仍有两个版本的 ZIP 与校验文件。证据 E01–E03；没有对正在使用的应用做交互验证。

```text
N01 完成代码与测试
  ↓
N02 手动提交
  ↓
N03 手动构建／打包
  ↓
N04 人工退出旧应用、选择产物与数据目录
  ↓
N05 手动启动，历史包仍留在磁盘
```

本需求不改变便签编辑界面；只有“关于”中的版本辨识信息随交付补充，无需重画便签 UI。

## 需求重定义

**原始诉求**：提高新改动到 Git 提交和本机新版本安装的效率，不保留历史 ZIP。

**最终目标**：测试过的同一份代码能以一个项目专属入口完成本地交付，不误开旧版、不换成空库、不混入别人的代码。

**异议**：本机安装不需要 ZIP；将打包改为按需分享，平时直接安装应用，比每次压缩再删除更简单。用户已接受。

**重定义后的需求**：保留“开发＋自动化和开发者验证”“本地交付收尾”两部分；各有项目入口，遇到真实阻断才询问。第一部分复用现有能力、按影响验证并自动准备交接；到达交接不自动执行第二部分。

版本 2 补充现状：第一部分此前只有散落的需求/开发/测试入口与第二部分的指纹接口，尚无项目统一入口；本轮仅新增操作指引和路由，不启动新便签功能开发。

## 新旧对照与差异

```text
N01 完成代码与测试〔修改 D01〕
  ↓ 交接同一份代码及实际验证结果
N02 核对并提交本次选定改动〔修改 D02〕
  ↓
N03 生成本机应用，不生成 ZIP〔修改 D03〕
  ↓
N04 正常退出确认的旧实例，沿用原数据目录并更新〔修改 D04〕
  ├─ 退出／安装／启动失败 → 明确部分成功，保留恢复材料，不清理旧包
  ↓ 成功
N05 核对运行版本，清理约定范围历史包〔修改 D05〕
```

上图为已批准目标业务顺序：提交与构建的具体实现顺序不改变“构建失败不安装”的要求，技术候选留给项目实施入口。最小例子：折叠逻辑测完又修改，旧流程可能直接安装；目标在交接核对处停止，补受影响验证后才继续。

版本 2 将 N01 展开为：描述改动 → 查当前实现 → 确认必要业务选择 → 开发 → 按影响验证与聚焦 Review → 必要时等待候选体验 → 自动交接 → 停止。N02–N05 仍需另行明确调用。最小例子：“标题条再窄一点”先厘清宽或高；明确后由执行者完成构建与隔离数据准备，用户不再寻找产物或传指纹。

## 用户故事与业务规则

- US01 As a 本机使用者, I want 一次调用完成本地交付, so that 不再重复选择产物、安装和清理。
- US02 As a 开发者, I want 明确交付的是测试过的代码, so that 不把测试结论套用到未验证修改。
- R01：交接包含改动范围、自动化验证、开发者操作验证、未验项和数据兼容性；测试代码变化必须补相应验证，未做不算通过。
- R02：只提交本次选定且核对过的改动；部分暂存或混杂内容不自动整文件提交，不修改无关暂存内容。
- R03：日常安装不生成 ZIP；分享包不是本轮能力。
- R04：固定安装到当前用户 Applications/PaperDock.app；只退出本轮确认的唯一旧实例，不强杀。数据目录须明确并沿用，保存失败或未知数据兼容性阻断安装。
- R05：成功启动核对后才清理 dist 直接子文件中本项目历史试用 ZIP 及对应校验文件；不递归、不跟随软链，不动数据与证据。安装期间可临时保留一份旧应用，成功后回收；失败保留恢复路径。
- R06：应用能辨识源码提交版本；启动成功只证明启动，不等于全功能验收。提交后失败须区分源码已提交与安装未完成，不自动撤销提交或回退数据。
- R07：第一部分复用现有确认、方案、实现与测试能力；材料按改动大小收敛，保留必要业务决策和正式审查要求，不重新确认已定规则。
- R08：用例预期只维护一次，开发、测试、Review 和用户体验引用同一份；只验证本次变化与直接影响，依据实际失败再扩大。自动化不能代替实际视觉、输入法或跨应用证据。
- R09：需要体验时提供可辨认候选及带明确隔离数据的启动命令；不覆盖用户应用、不复制日常库、不靠无参数双击，不退出用户当前实例。纯文档改动不构建应用。
- R10：执行者记录测试前指纹、真实结果与未验项，用户无需维护参数；待体验、失败或阻断不算完成，不生成本轮可交付批准。只有已完成或用户明确接受并更新范围后才交接，交接本身不授予提交安装权限。

## 不做什么与用例入口

- 不推送、发布、生成朋友分享包、设置自动更新服务或安装工具。
- 不新造第一部分流程引擎、后台监听、多 Agent 编排或便签功能；不执行便签数据迁移或降级。
- 不删除历史解压目录、测试证据、数据库或任意其他 ZIP。

用例：[两部分流程用例](test-cases.md)，版本 2；具体输入、操作和预期只在该文件维护。已由本轮对话确认核心规则并授权实施；未执行独立用例审查，不伪称已独立审查。验证仅临时 Git／安装目录与自有隔离实例；当前用户实例、正式 Git 提交和安装不作为本次实现验证的写入目标。
